Growser — how updates work

What each platform does to keep itself current, in plain terms. No marketing.

Growser is delivered one way per platform: on Windows through the Microsoft Store, on macOS as a notarized download that keeps itself current through Sparkle, on Linux as a package that adds our repository and then updates along with everything else on the machine. All three are described below.

Windows

  • Distribution. The Microsoft Store is the only channel. The package is MSIX; Microsoft signs it on submission, so there is no SmartScreen warning and the publisher is verified.
  • Updates. The Store keeps the browser current the same way it updates every other Store app — automatically, with no updater of ours running on the machine.
Had installed the old direct download? GrowserSetup.exe was offered here before the Microsoft Store listing existed. That channel is closed: direct installs stay on 152.26.826.0 and will not be offered anything newer. Install Growser from the Microsoft Store to keep receiving updates. The .exe itself remains on every GitHub release — Growser is open source, so anyone can build from the sources and compare against the published binary. That is a verification artifact, not an install path.

macOS

  • Distribution. An Apple Silicon (arm64) build, packaged as a notarized disk image Growser-mac-arm64.dmg on the same GitHub release. Download, open, drag Growser.app to /Applications. There is no Intel (x86_64) build yet.
  • Updates. The active updater on macOS is Sparkle: the browser reads a signed appcast at the URL compiled into it (https://growser.org/sparkle/stable-arm64/appcast.xml), which advertises Growser-mac-arm64.zip — the auto-update archive, ditto-zipped and signed with our EdDSA key — and installs it in place. The manual download button serves the .dmg above; both carry the same notarized build.
The channel is read off the build, not chosen. The appcast path is built from what the browser reports as its channel. Releases used to be non-official and reported developer, which is why older builds ask for sparkle/developer-arm64/; they have been official builds since the optimization and identity work, so the feed in use is stable-arm64. Neither name means a nightly: both have always been the same notarized release.

Linux

  • Distribution. A 64-bit package per family, both the same build: growser_<version>_amd64.deb for Debian and Ubuntu, growser-<version>-1.x86_64.rpm for Fedora and RHEL. There is no tarball, Flatpak or AppImage, and no 32-bit or ARM build.
  • Once the repository is on the machine, it installs by name — sudo apt install growser or sudo dnf install growser — and the command that starts it is growser. Before that it will not: no distribution ships a package under this name, so both answer with a plain error and install nothing.
  • Updates. Installing the package adds our repository and our signing key, so from then on the browser updates with everything else — apt upgrade or dnf upgrade. Removing the package takes both away again. Nothing of ours runs in the background: no updater, no cron job.
The repository, by hand. The packages write this for you on both families; it is here so you can read it before trusting it, or set it up without installing a package first. On Debian and Ubuntu, put our key in /usr/share/keyrings/growser.gpg (curl -fsS https://growser.org/growser-signing-key.pub | sudo gpg --dearmor -o /usr/share/keyrings/growser.gpg) and write /etc/apt/sources.list.d/growser.sources:
Types: deb
URIs: https://growser.org/apt/
Suites: stable
Components: main
Architectures: amd64
Signed-By: /usr/share/keyrings/growser.gpg

On Fedora and RHEL, /etc/yum.repos.d/growser.repo:
[growser]
name=growser
baseurl=https://growser.org/rpm/stable/x86_64
enabled=1
gpgcheck=1
gpgkey=https://growser.org/growser-signing-key.pub

The signing key is growser-signing-key.pub, fingerprint 9881 9EF6 618B 88A1 FA27 7488 2DD2 1359 5059 E6FD. It signs the apt Release and every .rpm, and it is not the key that signs anything else of ours.

Growser — как устроены обновления

Что каждая платформа делает, чтобы браузер оставался свежим. Без маркетинга.

На каждой платформе доставка своя: на Windows — через Microsoft Store, на macOS — нотаризованная загрузка, которая обновляет себя сама через Sparkle, на Linux — пакет, который добавляет наш репозиторий и дальше обновляется вместе со всем остальным на машине. Ниже — про все три.

Windows

  • Доставка. Единственный канал — Microsoft Store. Пакет в формате MSIX; Microsoft подписывает его при приёме, поэтому SmartScreen не предупреждает, а издатель подтверждён.
  • Обновления. Магазин обновляет браузер так же, как любое другое приложение из магазина — сам, и никакой наш апдейтер на машине не работает.
Ставили старую прямую загрузку? GrowserSetup.exe предлагался здесь, пока не появилось приложение в Microsoft Store. Этот канал закрыт: прямые установки остаются на 152.26.826.0, ничего новее им не предложат. Чтобы снова получать обновления, поставьте Growser из Microsoft Store. Сам .exe по-прежнему лежит в каждом выпуске на GitHub — Growser открыт, поэтому любой может собрать его из исходников и сравнить с опубликованным бинарником. Это артефакт для проверки, а не способ установки.

macOS

  • Доставка. Сборка для Apple Silicon (arm64), упакованная в нотаризованный образ Growser-mac-arm64.dmg в том же выпуске на GitHub. Скачать, открыть, перетащить Growser.app в /Applications. Сборки для Intel (x86_64) пока нет.
  • Обновления. На macOS работает Sparkle: браузер читает подписанный appcast по адресу, вшитому в сборку (https://growser.org/sparkle/stable-arm64/appcast.xml), где объявлен Growser-mac-arm64.zip — архив для автообновления, упакованный через ditto и подписанный нашим ключом EdDSA, — и ставит его поверх. Кнопка ручной загрузки отдаёт .dmg выше; внутри обоих один и тот же нотаризованный билд.
Канал не выбирают — его сообщает сама сборка. Путь к appcast складывается из того, каким каналом браузер себя считает. Раньше выпуски были неофициальными сборками и сообщали developer — поэтому старые версии спрашивают sparkle/developer-arm64/; после работ по оптимизации и идентичности они официальные, и фид называется stable-arm64. Ни то ни другое не означает «ночную сборку»: и там и там всегда был один и тот же нотаризованный выпуск.

Linux

  • Доставка. По одному 64-битному пакету на семейство, внутри одна и та же сборка: growser_<версия>_amd64.deb для Debian и Ubuntu, growser-<версия>-1.x86_64.rpm для Fedora и RHEL. Ни tarball, ни Flatpak, ни AppImage; 32-битных и ARM-сборок нет.
  • Когда репозиторий на машине, ставится по имени — sudo apt install growser или sudo dnf install growser, — а запускается командой growser. До этого не поставится: ни один дистрибутив не везёт пакета с таким именем, поэтому обе команды просто ответят ошибкой и ничего не установят.
  • Обновления. Установка пакета добавляет наш репозиторий и наш ключ подписи, и дальше браузер обновляется вместе со всем остальным — apt upgrade или dnf upgrade. Удаление пакета убирает и то и другое. Ничего нашего в фоне не работает: ни апдейтера, ни задания в cron.
Репозиторий вручную. На обоих семействах это делает сам пакет; здесь — чтобы можно было прочитать это до того, как довериться, или настроить без установки пакета. На Debian и Ubuntu положите наш ключ в /usr/share/keyrings/growser.gpg (curl -fsS https://growser.org/growser-signing-key.pub | sudo gpg --dearmor -o /usr/share/keyrings/growser.gpg) и напишите /etc/apt/sources.list.d/growser.sources:
Types: deb
URIs: https://growser.org/apt/
Suites: stable
Components: main
Architectures: amd64
Signed-By: /usr/share/keyrings/growser.gpg

На Fedora и RHEL — /etc/yum.repos.d/growser.repo:
[growser]
name=growser
baseurl=https://growser.org/rpm/stable/x86_64
enabled=1
gpgcheck=1
gpgkey=https://growser.org/growser-signing-key.pub

Ключ подписи — growser-signing-key.pub, отпечаток 9881 9EF6 618B 88A1 FA27 7488 2DD2 1359 5059 E6FD. Им подписаны Release в apt и каждый .rpm; больше ничего нашего этим ключом не подписано.
