Growser — how updates work

What each platform does to keep itself current, in plain terms. No marketing.

Growser is delivered one way per platform: on Windows through the Microsoft Store, on macOS as a notarized download that keeps itself current through Sparkle. Both are described below.

Windows

  • Distribution. The Microsoft Store is the only channel. The package is MSIX; Microsoft signs it on submission, so there is no SmartScreen warning and the publisher is verified.
  • Updates. The Store keeps the browser current the same way it updates every other Store app — automatically, with no updater of ours running on the machine.
Had installed the old direct download? GrowserSetup.exe was offered here before the Store listing existed. That channel is closed: direct installs stay on 152.26.826.0 and will not be offered anything newer. Install Growser from the Store to keep receiving updates.

macOS

  • Distribution. An Apple Silicon (arm64) build, packaged as a notarized disk image Growser-mac-arm64.dmg on the same GitHub release. Download, open, drag Growser.app to /Applications. There is no Intel (x86_64) build yet.
  • Updates. The active updater on macOS is Sparkle: the browser reads a signed appcast at the URL compiled into it (https://growser.org/sparkle/developer-arm64/appcast.xml), which advertises Growser-mac-arm64.zip — the auto-update archive, ditto-zipped and signed with our EdDSA key — and installs it in place. The manual download button serves the .dmg above; both carry the same notarized build.
Why the macOS channel is “developer”. The appcast path is built from the build’s channel, and our releases are non-official (no service keys, no ThinLTO, no exact-SDK gate), so the browser reports its channel as developer — hence sparkle/developer-arm64/. An official build would report stable and use sparkle/stable-arm64/. The name is honest about what the build is; it is not a “dev” build in the nightly sense.
