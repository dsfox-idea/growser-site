Growser — code signing policy

How our releases are signed, and who can authorise a signature.

Signing

Free code signing is provided by SignPath Foundation; the certificate is issued by SignPath. The private key never leaves SignPath's hardware security module — we cannot export it, and neither can anyone who compromises a machine of ours.

What we sign

Only binaries built from our own published sources: the browser, its installer and its libraries, built from dsfox-idea/brave-core (MPL-2.0), which is a fork of brave-core on top of Chromium. We do not sign third-party binaries.

macOS signing

macOS releases are signed with an Apple Developer ID certificate (Developer ID Application: Dmitry Golubnichiy (C3DL5896VG)), notarized by Apple, and the notarization ticket is stapled to the bundle. Notarization submits the archive to Apple, waits for a verdict, then staples the ticket — so the download verifies offline and Gatekeeper accepts it on first open with no “cannot be verified” warning. The signing identity and the notarization credentials live in the Apple Developer account and the build machine’s keychain, never in the repository; the release script injects the identity for one run only and removes it afterwards, so the daily unsigned build is unaffected.

Roles

RoleWhoWhat it means
Author Dmitry Golubnichiy (@dsfox) May commit to the repository directly.
Reviewer Dmitry Golubnichiy Reviews contributions from outside the team before they are merged.
Approver Dmitry Golubnichiy Authorises each signing request.

The project has one maintainer today, so one person holds all three roles. This page is updated when that changes — the point of listing them is that the list is accurate, not that it is long.

Account security

  • Multi-factor authentication is required on the GitHub account that owns the repositories and on the SignPath account.
  • Signing is requested from our release process; each request is approved by an Approver above.

Privacy

This page and the rest of growser.org are static and set no cookies. We collect nothing here. What the browser itself sends, and to whom, is documented in the repository rather than summarised in marketing terms — see the sources. Signing itself involves SignPath receiving the binaries we ask it to sign; see SignPath's privacy policy.

Reporting a problem

If you find a signed Growser binary that we did not publish, or a signature that does not verify, please open an issue on the repository.
